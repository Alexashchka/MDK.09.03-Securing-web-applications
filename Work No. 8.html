Практическая работа №8

Тема работы

Название:Сложные пароли. Двухфакторная авторизация

Цели и задачи

Задачи:

  • получить навыки проверки сложности пароля;
  • изучить основные способы отправки сообщений на почту;
  • обучиться методам и средствам контролирования сессии.

Видео выполнения практической работы

Теоретический материал

Представленно в виде лекций.

Порядок выполнения работы

Шаг 1. Установить виртуальную машину OpenServer. Развернуть тестируемый сайт.
При разработке использовать систему контроля версий, с промежуточными комментариями.
Шаг 2. При регистрации пользователя реализовать проверку пароля по следующим условиям (со стороны JavaScript и PHP):
- количество символов более 8;
- в пароле используются латинские буквы;
- в пароле используются символы;
- в пароле используются цифры;
- одна из букв является заглавной.
Шаг 3. При неправильном вводе пароля, уведомлять пользователя.
Шаг 4. Пароль, хранящийся в базе данных, необходимо зашифровать.
Шаг 5. При авторизации, отправить сообщение на указанную в профиле пользователя почту, сформировав уникальный код авторизации, состоящий из 6 цифр. Авторизация проходит только при успешном совпадении отправленного кода на почту и введённого в специальное окно.
Шаг 6. Реализовать функционал, когда пользователь авторизован в одной системе.
Пример: при авторизации пользователя на сайте edu.permaviat.ru, в обычном браузере, и браузере в режиме инкогнито. Сайт позволит авторизоваться только на одном из браузеров.

Шаг 7. Ответить на контрольные вопросы.
Шаг 8. Оформить отчёт.

Контрольные вопросы

1) для чего используются сложные пароли?
2) где лучше производить проверку на корректность пароля, на сервере или клиенте?
3) стоит ли указывать на разных сайтах один и тот же пароль?

Дополнительное задание


Задание на оценку «Хорошо», разработать функционал для истечения пароля. Пароль пользователя истекает каждые N дней, с последнего дня его изменения.
Задание на оценку «Отлично», необходимо выполнить задание на оценку «Хорошо», разработать функционал определение местоположения пользователя при помощи API. Если пользователь авторизовывается на достаточно далёком расстоянии от предыдущего места авторизации, реализовать дополнительную проверку, по указанной почте в профиле пользователя.
